# Bit-Chess 사양 (SPEC)

## 역할

너는 Flutter·Android BLE·모바일 보안에 익숙한 개발자다. 아래 사양으로 **블루투스만으로 두 폰이 대전하는 체스 앱**을 만든다. 작업은 단계별로, 사람이 지시한 단계만 한다. 결과물은 실제로 폰 두 대에 설치해 비행기 안에서 쓸 앱이다. **보안은 기능만큼 중요하다.** 앱 자체의 보안과 공개 GitHub 저장소의 보안 모두 "보안 (최우선)" 항목을 반드시 지켜라.

## 프로젝트 정보

- 저장소: https://github.com/movingmin/Bit-Chess.git (**Public**). 작업 전에 현재 내용(빈 저장소인지, 기존 커밋이 있는지)부터 확인한다. force push는 하지 않는다.
- 개발 환경: Samsung Galaxy Book4, **Windows 11**. Flutter SDK + Android Studio(Android SDK·에뮬레이터) + Git for Windows. 셸 예시는 PowerShell 기준으로 쓴다.
  - 프로젝트 경로에는 공백·한글을 넣지 않는다(예: `C:\dev\Bit-Chess`). Gradle·NDK 빌드가 깨질 수 있다.
  - BLE는 에뮬레이터로 시험할 수 없으므로 실기기 Android 2대를 USB/무선 디버깅으로 연결해 시험한다.
- 1차 타깃은 **Android 전용**. 맥이 없어서 iOS는 "iOS (선택)" 항목대로 막히지 않게 설계만 한다.

## 목표

- Chess.com처럼 깔끔한 UI·조작감의 1:1 체스 앱. 화면 구성, 보드 조작, 시계, 대국 후 흐름은 Chess.com을 기준으로 삼는다.
- **인터넷·와이파이 없이, 블루투스(BLE)만으로** 옆자리 친구 폰과 대전한다. 기본 사용 환경은 비행기 모드에서 블루투스만 다시 켠 상태다.
- 연결은 bitchat(https://github.com/permissionlesstech/bitchat)에서 아이디어만 가져와 **서버 없이 BLE GATT 1:1 직결**로 한정한다(호스트 = peripheral/광고, 게스트 = central). 서버, 계정, 와이파이 다이렉트, Google Nearby Connections(와이파이도 같이 씀)는 쓰지 않는다. bitchat의 다중 홉 메시 중계와 Noise 프로토콜 전체 구현은 범위 밖이다.

## 필수 기능 (빠지면 미완성)

1. **닉네임 설정**: 첫 실행 때 입력받아 기기에 저장한다. 설정 화면에서 바꿀 수 있고, 연결할 때 상대에게 전달한다.
2. **방 생성 / 가입**
   - 방 만들기(Host): 방 이름(기본값 "{닉네임}의 방")과 시간 제한(무제한 / 3분 / 5분 / 10분 / 15+10 / 사용자 지정)을 고르고 BLE 광고를 시작한다. 방 이름은 UTF-8 22바이트까지만 입력된다(한글 7자, 영어 22자). 기본값이 넘치면 닉네임을 글자 단위로 잘라 "…의 방"으로 줄인다.
   - 방 찾기(Join): 주변 방을 스캔해 방 이름, 시간 제한(프리셋 또는 "사용자 지정"), 신호 세기를 목록으로 보여주고, 탭하면 입장한다. 호스트 닉네임과 사용자 지정 시간의 세부 값은 입장 뒤 `HELLO`·`ROOM_INFO`로 받아 대기실에 보여준다.
   - 방은 2인 전용이다. 찬 방은 광고를 멈춘다.
3. **흑/백 배정**: 방을 만들 때 "랜덤 / 내가 백 / 내가 흑" 중에 고르며 기본값은 랜덤이다. **재대국도 매번 랜덤**이다(색 교대가 아님). 랜덤은 한쪽이 조작할 수 없게 commit-reveal로 정한다: 양쪽이 난수의 해시를 먼저 보내고, 둘 다 받은 뒤 난수를 공개해 XOR 결과로 색을 정한다. 결과는 양쪽 화면에 보여준다.
4. **대국**
   - 규칙 전부: 캐슬링, 앙파상, 프로모션(선택 UI), 체크, 체크메이트, 스테일메이트, 50수, 3회 반복, 기물 부족 무승부.
   - 탭-탭과 드래그 이동을 둘 다 지원한다. 이동 가능한 칸, 마지막 수, 체크를 강조한다. 내 색이 아래에 오도록 보드 방향을 맞추고, 프리무브(상대 차례에 미리 두기)도 넣는다.
   - 체스 시계, 기권, 무승부 제안/수락/거절, 재대국.
   - 효과음(이동·잡기·체크·종료), 진동 on/off.
5. **인게임 채팅**: 대국 화면 안의 텍스트 채팅. 보드를 가리지 않게 하단 시트나 탭으로 넣는다. 상대 메시지가 오면 배지를 띄우고, 빠른 메시지(예: "좋은 수!", "잠깐만")를 몇 개 둔다. 대국 시작 전 대기실에서도 채팅이 돼야 한다. 채팅 끄기(상대 메시지 숨김) 옵션도 둔다.
6. **기보 저장**
   - 대국이 끝나면(중단 포함) 표준 PGN으로 자동 저장한다. 헤더: Event, Date, White, Black(닉네임), Result, TimeControl.
   - "지난 대국" 목록에서 기보 다시보기(앞/뒤 이동, 처음/끝)를 할 수 있다.
   - PGN 파일을 내보내거나 공유할 수 있다(Android 공유 시트, 또는 사용자가 고른 위치에 저장).
   - 대국 중 앱이 꺼져도 진행 중인 판이 남아 있어서, 다시 연결하면 이어서 둘 수 있어야 한다.
7. **혼자 두기(Pass & Play)**: 한 폰에서 번갈아 두는 모드. 기보 저장도 똑같이 된다.

## 블루투스 설계

- **역할**: 호스트는 GATT 서버로 커스텀 서비스 UUID를 광고하고, 게스트는 스캔해서 연결한다. 연결은 1개만 받고, 나머지 연결 시도는 즉시 끊는다.
- **광고 데이터**: 광고 패킷에는 서비스 UUID만, 스캔 응답에는 제조사 데이터(회사 번호 2바이트 + 세션마다 새로 만드는 랜덤 방 ID 4바이트 + 시간 프리셋 1바이트 + UTF-8 방 이름 최대 22바이트)를 넣는다. 시간 프리셋: 0 무제한, 1 3분, 2 5분, 3 10분, 4 15+10, 255 사용자 지정(세부 값은 `ROOM_INFO`). 광고 패킷은 31바이트로 제한되므로 나머지는 연결 뒤 `ROOM_INFO`로 받는다. 기기 고유 ID는 광고에 넣지 않는다. 회사 번호(시험용 0xFFFF 등)를 배포 앱에 써도 되는지는 확인 필요. BLE 5 확장 광고는 두 폰 지원 여부 확인 뒤 검토한다.
- **캐릭터리스틱**: 게스트→호스트는 write(with response), 호스트→게스트는 notify. MTU를 협상하고, 메시지가 MTU보다 길면 쪼개서 보내고 받는 쪽에서 다시 합친다.
- **Flutter 플러그인**: `flutter_blue_plus`는 central 전용으로 알고 있다(확인 필요). peripheral 쪽(GATT 서버·광고)은 지원 플러그인을 조사해서 고르거나 Kotlin 플랫폼 채널로 직접 구현한다. 선택 근거를 README에 적는다.
- **프로토콜**: 암호화된 프레임 안에 길이 접두 + JSON을 담는다. 모든 메시지에 `type`, `seq`, `ver`를 붙인다.
  - `HELLO {nickname, appVersion, pubKey}` / `ROOM_INFO {name, timeControl, colorMode}`
  - `COLOR_COMMIT {hash}` / `COLOR_REVEAL {nonce}`
  - `GAME_START {gameId, whiteNick, blackNick, timeControl}`
  - `MOVE {gameId, ply, uci, moverRemainingMs}` → `ACK {ply}`
  - `CHAT {id, text}` → `ACK`
  - `RESIGN` / `DRAW_OFFER` / `DRAW_RESPONSE {accept}` / `REMATCH_OFFER` / `REMATCH_RESPONSE`
  - `SYNC_REQUEST` / `SYNC {gameId, uciMoves[], whiteRemainingMs, blackRemainingMs}`: 재연결할 때 수순 전체를 맞춘다.
  - `PING` / `PONG`: 연결이 살아 있는지 확인한다.
- **시계 동기화**: 두 폰의 기기 시각이 다르므로 **절대 시각(타임스탬프)으로 시간을 계산하지 않는다.** 수를 둔 쪽이 자기 단조 시계(monotonic clock)로 잰 **남은 시간**을 `moverRemainingMs`로 보내고, 받는 쪽은 그 값을 그대로 쓴다. 상대 차례 동안의 카운트다운은 각자 화면 표시용이고, 기준값은 항상 수를 둔 쪽이 보낸 값이다.
- **정합성**: 두 폰 모두 수를 직접 검증한다. 불법 수, `ply` 불일치, 중복 메시지는 버리고 SYNC를 요청한다. ACK가 오지 않으면 재전송한다.
- **연결 유지·끊김**
  - Android는 백그라운드에서 BLE 연결과 GATT 서버를 끊을 수 있다. 대국 중(대기실 포함)에는 화면 꺼짐을 막고(wakelock), 필요하면 `connectedDevice` 타입 foreground service로 BLE 연결을 유지한다. 알림에는 "대국 중"만 표시한다.
  - 그래도 끊기면 대국을 끝내지 말고 "재연결 중…"을 띄운 뒤 자동으로 다시 붙어 SYNC한다. 끊긴 동안 시계는 멈춘다. 일정 시간(예: 2분)이 지나도 붙지 않으면 "중단" 상태로 기보를 저장한다.
- **권한**: Android 12+는 `BLUETOOTH_SCAN`(`neverForLocation` 플래그), `BLUETOOTH_CONNECT`, `BLUETOOTH_ADVERTISE`를, 11 이하는 위치 권한을 쓴다. 거부되거나 블루투스가 꺼져 있으면 무엇을 켜야 하는지 안내 화면을 띄운다.

## 보안 (최우선)

### 앱 / 통신

- **종단 암호화**: 연결 직후 양쪽이 일회용 X25519 키를 교환하고 HKDF로 세션 키를 만든다. 이후 모든 메시지는 AES-256-GCM이나 ChaCha20-Poly1305로 암호화·인증한다(Dart `cryptography` 패키지 등 검증된 라이브러리 사용, 암호를 직접 구현하지 않음). 논스는 메시지마다 증가하는 카운터로 만들고, 재전송(replay)되거나 순서가 어긋난 프레임은 버린다.
- **확인 코드(SAS)**: 공유 비밀에서 6자리 숫자를 뽑아 양쪽 화면에 띄우고, 두 사람이 같은 숫자인지 확인하고 "일치"를 눌러야 대국이 시작된다. 중간자 공격과 엉뚱한 기기와의 연결을 막는다.
- **입력 검증**: 상대가 보낸 데이터는 전부 신뢰하지 않는다.
  - 다시 합친 메시지 최대 크기(예: 8KB)와 조각 수에 상한을 둔다.
  - 알 수 없는 `type`이나 스키마가 틀린 메시지는 버린다.
  - 닉네임은 1–16자, 채팅은 200자까지 허용하고 제어 문자·양방향 제어 문자(RTL override 등)를 제거한다.
  - 채팅은 평문 텍스트로만 표시한다(링크·마크다운 해석 금지).
  - 메시지 속도 제한(예: 채팅 초당 2개)을 두고, 넘치면 버린다.
  - 파서에는 깨진 입력·초대형 입력을 넣는 퍼징성 단위 테스트를 단다.
- **핸드셰이크 타임아웃**: 연결 후 일정 시간 안에 키 교환과 HELLO가 끝나지 않으면 연결을 끊는다.
- **네트워크 권한 없음**: 릴리스 `AndroidManifest.xml`에 `INTERNET` 권한을 넣지 않는다(디버그 빌드만 Flutter 기본값 허용). 앱이 외부로 통신할 수 없다는 것을 구조로 보장한다. 분석·크래시 리포트·광고 SDK는 넣지 않는다.
- **로컬 데이터**: 기보와 설정은 앱 전용 저장소에 둔다. 밖으로 나가는 것은 사용자가 직접 내보낼 때뿐이다. `android:allowBackup="false"`, 릴리스는 debuggable 끔 + R8 축소를 적용한다.
- **권한 최소화**: 위 블루투스 권한 외에는 꼭 필요한 것만 쓴다. 각 권한이 왜 필요한지 README에 적는다.

### GitHub (Public 저장소)

- **첫 커밋 전에** Flutter/Android용 `.gitignore`를 먼저 넣는다. 아래 파일은 절대 커밋하지 않는다: `*.jks`, `*.keystore`, `key.properties`, `local.properties`, `.env*`, `*.p12`, `google-services.json`, `.omp/`(로컬 에이전트 설정), 서명 비밀번호, 개인 경로가 들어간 설정 파일, 빌드 산출물(`build/`), 테스트 중 생긴 PGN·로그·스크린샷.
- **커밋 전마다** `git status`와 `git diff --staged`를 확인한다. gitleaks(또는 동급 도구)를 pre-commit 훅으로 걸고, CI에서도 돌린다.
- GitHub 저장소 설정에서 Secret scanning, Push protection, Dependabot alerts·security updates를 켜고, `main` 브랜치를 보호한다. 설정 방법을 README나 `SECURITY.md`에 적어 사용자가 직접 켜게 한다.
- 커밋 작성자 이메일은 GitHub noreply 주소(`ID+username@users.noreply.github.com`)를 쓰도록 안내한다. 실명·개인 이메일·로컬 경로(`C:\Users\...`)가 커밋, 코드 주석, 로그, 이슈에 남지 않게 한다.
- **릴리스 서명 키**: 키스토어는 저장소 밖(예: `C:\keys\`)에 두고 오프라인으로 따로 백업한다. 키를 잃으면 앱을 업데이트할 수 없다. CI에서 서명한다면 키스토어를 base64로 GitHub Actions Secrets에 넣고, 로그에 절대 출력하지 않는다. 기본은 로컬 서명이다.
- GitHub Actions는 `permissions: contents: read`를 기본으로 두고, 서드파티 액션은 커밋 SHA로 고정한다.
- 의존성은 pub.dev에서 유지보수가 활발하고 검증된 패키지만 쓴다. 앱이므로 `pubspec.lock`은 커밋한다. 새 패키지를 추가할 때는 이유를 커밋 메시지에 적는다.
- 릴리스 APK를 GitHub Releases에 올릴 때는 SHA-256 체크섬도 함께 올린다.
- **비밀이 한 번이라도 커밋되면** 히스토리를 고쳐 쓰는 것으로 끝내지 말고, 이미 유출된 것으로 보고 해당 키·비밀번호를 교체한다. 즉시 사용자에게 알린다.
- `SECURITY.md`(취약점 제보 방법)와 `LICENSE`를 둔다. 라이선스는 아래 "엔진 분석" 항목의 GPL 조건을 반영해 정한다.

## 엔진 분석 — 복기 + 분석 보드 (선택 — 성능이 나올 때만)

- **대국 후 복기**: 끝난 판을 Chess.com의 "게임 리뷰"처럼 돌아본다. 평가 막대, 수마다 최선수 화살표, 실수·악수·블런더 표시(센티폰 손실 기준), 최선 수순 보기.
- **분석 보드**: 대국과 상관없이 혼자 판을 놓고 분석하는 화면. Chess.com/lichess의 분석 보드처럼 만든다.
  - 위치 편집기: 말을 끌어다 놓기, 지우기, 판 비우기, 초기 배치, 차례·캐슬링 권리 설정. 합법적인 위치가 아니면 분석을 막고 이유를 보여준다.
  - FEN 붙여넣기·복사, PGN 불러오기(저장된 기보나 붙여넣은 기보).
  - 양쪽 수를 직접 두며 변화수 탐색(되돌리기, 갈래 수순). 실시간 평가 막대, 최선 수순 1–3개(MultiPV), 엔진 켜기/끄기.
  - 복기 중인 판에서 "이 위치를 분석 보드로" 버튼으로 바로 넘어간다.
- 엔진 후보: `multistockfish`(lichess.org 공개, Stockfish 19, Android/iOS), `stockfish`(Dart FFI). 둘 다 2026-10-09 pub.dev에서 확인했다. 실제 동작·용량·유지보수는 확인 필요.
- **NNUE 신경망 파일**: 이 앱에는 `INTERNET` 권한이 없으므로 **실행 중에 내려받는 구조는 쓸 수 없다.** 네트워크 파일은 반드시 APK 안에 넣는다.
  - `multistockfish` README(2026-10-09 확인) 기준: `StockfishFlavor.light`는 약 1MB짜리 작은 NNUE가 내장돼 있어 따로 받을 필요가 없다. `latestNoNNUE`는 `.nnue` 파일 경로를 따로 넘겨야 한다.
  - 기본값은 `light`(내장)로 한다. 큰 NNUE가 꼭 필요하면 asset으로 APK에 넣고 첫 실행 때 앱 저장소로 복사해 쓴다. 용량 증가를 보고한다.
  - Stockfish 16부터 classical 평가가 제거된 것으로 안다(확인 필요). 그러니 "NNUE가 없으면 classical로 대체" 같은 fallback은 기대하지 말고, 엔진을 못 띄우면 분석 기능을 끄고 이유를 보여준다.
- **공정성**: BLE 대국이 진행 중일 때는 엔진·분석 보드를 열 수 없게 막는다. 대국 화면에서 분석 보드로 가는 경로를 두지 않는다. 복기와 Pass & Play에서는 쓸 수 있다.
- 성능: 복기는 수 하나당 시간 제한(예: 0.5–1초), 분석 보드는 무한 분석이되 화면을 떠나면 즉시 멈춘다. 스레드 수 제한, 진행률 표시, 취소 버튼을 둔다. 실기기에서 40수짜리 판 전체 분석 시간, 분석 보드 10분 사용 시 발열·배터리, APK 크기 증가를 재서 보고한다.
- **라이선스**: Stockfish는 GPLv3이다. 엔진을 넣으면 앱 전체를 GPLv3로 공개해야 한다(확인 필요). 저장소가 Public이므로 GPL-3.0 `LICENSE`를 두면 된다. 엔진을 넣지 않으면 MIT 등도 가능하다.
- **포기 기준**: 분석이 너무 느리거나, APK가 지나치게 커지거나, 빌드가 불안정하면 엔진은 넣지 않는다. 그래도 위치 편집기·FEN/PGN 기능과 수를 직접 두는 분석 보드(엔진 없음)는 남긴다. 그 위에 "PGN/FEN 복사 → 인터넷이 될 때 lichess 분석 보드에 붙여넣기" 버튼을 둔다. 어느 쪽으로 정했는지와 근거를 보고한다.

## 기술 스택

- Flutter(최신 stable), Dart. 상태 관리는 하나만 골라 일관되게 쓴다(Riverpod 권장).
- 체스 규칙: 검증된 Dart 패키지(예: `chess` 또는 lichess의 `dartchess` — 유지보수 상태와 라이선스 확인 필요)를 쓰고 직접 짜지 않는다. 보드 UI는 직접 그리거나 패키지를 쓴다.
- 로컬 저장: 닉네임·설정은 `shared_preferences`, 기보는 PGN 파일 또는 SQLite.
- 기물 이미지·효과음: 라이선스가 확실한 것만 쓰고(예: lichess의 cburnett 세트, 확인 필요) 출처를 README에 적는다.

## iOS (선택)

- Android를 먼저 끝까지 완성한다.
- 블루투스 계층은 `Transport` 인터페이스 뒤에 숨겨서, 나중에 iOS(CoreBluetooth)를 붙여도 앱 로직이 바뀌지 않게 한다. 프로토콜은 플랫폼 중립으로 두어 Android↔iPhone 대전 가능성을 남긴다.
- 맥 없이 iOS를 빌드하는 경로(GitHub Actions macOS 러너, Codemagic 등)와 실기기 설치 조건(Apple 개발자 계정, 서명)을 조사해 README에 "가능/불가·비용"만 정리한다. 구현은 하지 않는다.

## 진행 방식

- 작업은 단계별로 한다. 사람이 "N단계"를 지시하면 그 단계만 하고 멈춘다. 단계 목록과 현재 상태는 `docs/PROGRESS.md`에 있다.
  - 0 저장소·보안 기반 / 1 체스 핵심(Pass & Play·기보) / 2 BLE 기술 검증 / 3 닉네임·방·대기실 / 4 암호화·확인 코드·랜덤 색 / 5 대국 동기화·시계 / 6 채팅 / 7 연결 유지·재연결·복구 / 8 릴리스 빌드·보안 점검 / 9 (선택) 엔진 분석(9a 분석 보드 → 9b 엔진 → 9c 복기)
- 단위 테스트 대상: 규칙 엔진 연동, 프로토콜 직렬화, 메시지 쪼개기/합치기, 암호화 왕복·변조 감지·재전송 거부, 입력 검증, commit-reveal, PGN 생성.
- 단계가 끝날 때마다 무엇이 되고 무엇이 남았는지, 그리고 **push 전에 보안 체크리스트를 통과했는지** 보고한다. push는 사람이 검증을 마치고 허락한 뒤에만 한다.

## 완료 기준 (실기기 Android 2대로 확인)

- [ ] 두 폰 모두 **비행기 모드 + 블루투스만 켜고 와이파이는 끈 상태**에서 아래가 모두 된다.
- [ ] 닉네임 설정 → A가 방 만들기(랜덤 색) → B 목록에 방이 보임 → 입장 → 양쪽에 같은 6자리 확인 코드 → "일치" 후 색 배정 표시.
- [ ] 한 판을 체크메이트까지 끝낸다. 캐슬링·앙파상·프로모션을 한 번씩 거친다.
- [ ] 대국 중에도, 대기실에서도 채팅이 양방향으로 된다. 201자 이상 입력·제어 문자는 걸러진다.
- [ ] 끝난 판이 양쪽에 PGN으로 저장되고, 다시보기와 내보내기가 된다. 내보낸 PGN을 lichess 분석 보드에 붙여 넣으면 오류 없이 읽힌다.
- [ ] 대국 중 화면을 꺼 두거나 앱을 백그라운드로 보냈다가 돌아와도 연결이 유지된다.
- [ ] 대국 중 한쪽 블루투스를 10초 껐다 켜면 자동으로 다시 붙고 수순·시계가 맞는다.
- [ ] 대국 중 앱을 강제 종료했다 다시 열면 같은 판으로 돌아간다.
- [ ] 무승부 제안·기권·재대국(색 다시 랜덤)이 된다.
- [ ] 릴리스 APK의 매니페스트에 `INTERNET` 권한이 없다(`aapt dump permissions` 등으로 확인).
- [ ] 저장소 전체 히스토리에 gitleaks를 돌려 결과가 0건이다. 키스토어·`key.properties`·`local.properties`가 추적되지 않는다.
- [ ] `flutter build apk --release`로 만든 APK, SHA-256, 설치 방법이 README에 정리돼 있다.
- [ ] (엔진을 넣은 경우) 처음 설치한 폰을 **비행기 모드로 켠 첫 실행부터** 분석 보드와 복기가 동작한다(NNUE를 내려받지 않음). 위치 편집기로 만든 임의 위치를 분석할 수 있다. BLE 대국 중에는 분석 보드에 들어갈 수 없다.
